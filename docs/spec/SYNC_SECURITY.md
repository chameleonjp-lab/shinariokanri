# 端末内保存・同期・権限仕様 1.0（規範・レビュー案）

対応: REQ-B23、REQ-F29/F30/F33–F35、REQ-N06–N11/N14/N15。端末内保存、端末間同期、公開用投影は別の機能として扱う。

## 保存状態

| 表示 | 確定していること | 次の扱い |
| --- | --- | --- |
| 編集中 / 未保存 | 入力だけが変わった | タブを閉じる前に保存または一時出力 |
| 端末内保存済み | ローカルトランザクション成功 | 通信なしで再開可。外部バックアップの代わりとはしない |
| 送信待ち | 保存済みコマンドがoutboxにある | 取得済み作品は編集継続。成功ackまで保持 |
| 同期中 | 送信または受信検証中 | 失敗なら再試行可能、未確定変更は保持 |
| 同期済み | サーバーrevisionと自分の送信が一致 | 他端末の未送信編集がないことまでは保証しない |
| 食い違いあり | 同じ項目/削除対編集の競合 | 両案と共通元を保持して比較へ |
| 保存失敗 / 認証切れ / 権限変更 | 完了していない | 理由と未保存/未送信範囲を示し、勝手に消さない |

オフライン使用はアプリと作品が取得済みの場合。初回起動、未取得素材、外部Web資料を通信なしに取得できるとは表示しない。アプリ更新やIndexedDBの形式移行は編集と競合しない安全地点で行い、先に復元点を用意する。

WebKitは保存容量制限や削除の可能性を説明している（[T01](../research/SOURCES.md)）。persist要求やインストールで永久保持を保証しない。本製品では保存失敗の入力保持、専用ファイル出力と空環境復元を必須にする。端末内履歴とブラウザー保存の全消去は同時に失われ得るので、外部に書き出した完全ファイルを復元基準とする。

## 同期のプロトコル

- コマンドはoperationId、projectId、対象ID、baseRevision、変更フィールドと旧値hashを持つ。サーバーは認証・membership・対象範囲・型/参照を検査して一括適用する。
- サーバー確定revisionを比較して更新する。端末時計や最終書込時刻だけで勝者を決めない。operationIdを冪等キーとし、同じ操作の再送は同じackを返す。HTTP成功だけではなく適用revisionと結果を確認する。
- 異なるフィールドを双方が変えた場合は共通元から三方向比較し、互いに触れていない値だけ自動統合する。同じフィールドを別の値に変えた場合は競合。全RichTextの一フィールドを最小の競合単位とし、文字単位の自動統合を既定にしない。両方が同じ値なら同一変更として処理できる。
- 順序付き配列の双方並べ替え、片方の削除と片方の編集、親関係の変更等は競合。削除を黙って復活させず、削除/復元/別案として保持のいずれかを選ぶ。
- 競合画面は共通元、端末案、サーバー案、影響参照を提示する。採用または組合せを新しい解決コマンドとして保存し、元案を履歴へ残す。解決中の更なる更新はrevision再検査が必要。
- ackを端末内へ確定してからoutboxを除く。送信後通信が切れた場合は再送し、二重effectを起こさない。Realtimeは変更通知の手段であり、競合解決や確定の代わりにしない。

添付は内容hashで識別し、bytes取得/送信とメタデータを段階化する。未アップロードbytesの添付がある場合、作品本文の端末保存とクラウド添付完了を分けて表示する。共有先に未取得添付を「完成済み」と出さない。不要blobの削除は参照と公開snapshotを検査してから行う。

## 認証と役割

未ログインでも端末内の個人作品を編集・書き出しできる。端末間同期と共同作業は認証付き。ローカル作品を同期へ移す際は新しいprojectとmembershipを作り、既存の別作品へ名前だけで混ぜない。

| 役割 | 取得 | 指摘 | 編集 | 共有設定・削除・所有権 |
| --- | --- | --- | --- | --- |
| owner | 自分の作品の全範囲 | 可 | 可 | 可。最後のownerを削除不可 |
| editor | 許可された作品編集範囲 | 可 | 可 | 不可 |
| reviewer | 許可された投影snapshot | 可 | 本文不可 | 不可 |
| reader | 許可された投影snapshot | 不可 | 不可 | 不可 |
| 非メンバー | 公開された投影のみ | 不可 | 不可 | 不可 |

editorは許可された編集対象の作者情報を取得する。reviewer/readerには正本の一部をUIで隠したデータを渡さず、投影snapshotだけを渡す。閲覧範囲にない対象へのコメントID差替えを拒否する。共有期間・失効・対象版・投影範囲を持ち、共有リンクを作品の秘密キーにしない。実装先の認証手段はWP17で固定し、ブラウザーにserver secretを置かない。

レコードのprivateはownerだけが取得する領域。共同編集で共有するteamは許可されたowner/editorの編集範囲に限る。新規レコードは作品のdefaultVisibilityを継承し、個人作品はprivate、ownerが共同編集を有効にした作品はteamを選べる。editorは自分のroleや公開範囲を拡張できない。reviewer/readerへの共有は別のprojectionを明示生成する。

権限撤回後は新規取得/更新/素材取得を拒否し、次の通信時に権限のなくなったローカルキャッシュを処理する。既に受け取ったファイル・オフラインコピーを遠隔で必ず消去できるとは保証しない。許可を得ていない端末へ最初から作者正本を送らないことを保護の基準とする。

クラウド由来キャッシュはaccountIdで分離し、別アカウントの画面/検索へ出さない。明示ログアウト前に未送信/未保存を一覧化し、同期または専用出力へ誘導する。破棄を選ぶ場合は対象を確認し、無言で削除しない。ログアウト完了後は認証情報とそのaccountの作者キャッシュを除去する。認証期限切れはログアウトと区別し、既存の未送信を保って再認証できる。ゲストのローカル作品は別領域で、共同作業の正本として勝手に共有しない。

秘密の素材はJWT付き取得を基本とする。署名URLを使う場合は5分以下とし、発行済みURLが期限内に利用され得ることを明示する。即時アクセス停止が必要な範囲へ署名URLを使わず、権限撤回後は新しいURLの発行を拒否する。既取得bytesの撤回は保証しない。

## Supabaseを採用する場合の必須規則

これは同期の参照構成であり、このPRではプロジェクトやDBを作成しない。実装時は公式資料と変更履歴を再確認する。

- exposed schemaの全テーブルにRLSを設定する。project_idのmembershipをサーバー管理テーブルで判定し、ユーザーが編集できるuser_metadataを権限の根拠にしない。
- SELECT/INSERT/UPDATE/DELETEを別に試験する。UPDATEは旧行のUSINGと更新後のWITH CHECK、必要なSELECT権限を用意し、project_id/owner_idを差替えて他作品へ移せないようにする。
- クライアントはpublishable keyとユーザーJWTだけを使う。service_role/secret/JWT署名秘密はブラウザー、リポジトリ、ログへ置かない。管理APIを権限回避のために作らない。
- private添付はprivate bucketとstorage.objectsのpolicyを使う。upload/download/update/deleteと署名URLの範囲・期限を検証する。public bucketへ作者素材を入れない。
- 公開投影を正本のJSON列へ同居させて閲覧者へ渡さない。限定閲覧は投影専用テーブル/非公開API等にし、正本へのSELECTは拒否する。RLSは行境界なので、同じ行の秘密フィールドを隠す代替にならない。
- viewは対応版でsecurity_invokerを使うか非exposed領域へ置く。RPCは所有権・membershipと参照範囲を内部でも確認し、必要時のみ権限を限定して使用する。
- migrationとpolicyをバージョン管理し、非メンバー・他作品メンバー・reader/reviewer/editor/owner・失効JWTで直接APIの権限試験をする。UI操作だけで合格にしない。

根拠: [RLSの公式資料](https://supabase.com/docs/guides/database/postgres/row-level-security)、[Storageの公式資料](https://supabase.com/docs/guides/storage/buckets/fundamentals)。membership検索索引、参照外キー、revisionの原子更新はWP17で実測・検証する。既存の別アプリ用接続先を流用しない。

## 秘密情報の投影

投影は許可ID・kind・章/経路・表示名・除外項目を指定し、その結果から本文、検索索引、地図、図、索引、集計、参照元、リンク、素材を再生成する。隠す秘密の本名、alias、家系、ID、ファイル表示名、コメント引用、作者メモ、参照件数、断片表示を元から送信しない。

公開データ内のIDも必要に応じ公開専用IDへ写し、隠された正本IDへの外部リンクを残さない。対象を隠すと説明不能になる文脈は、作者が匿名化/代替文/除外を選ぶ。safe projectionを作れない場合は公開出力を停止し対象を示す。未確定の秘密判定を安全として扱わない。

AT-E05ではネットワーク応答、API、検索、全文、地図、関係図、素材名、索引、コメント、リンク、参照数を確認する。AT-E06では二端末競合・重複送信・削除対編集・認証失効を検証する。
