# 設計判断と未確定条件

この文書は実装に進むための基準案。要件そのものは[要件仕様書](../spec/REQUIREMENTS.md)に従う。リポジトリはREADMEだけの初期状態であり、本PRにアプリ実装・migration・デプロイは含まない。

## 基準構成

| 層 | 基準案 | 理由・検証点 |
| --- | --- | --- |
| UI | React + TypeScript + ViteのWebアプリ | 全端末で同じ情報と操作規則。幅で配置を変える。具体package版は導入時に固定 |
| ドメイン | 時間、条件/状態、参照、投影、出力を純粋な処理へ分離 | 図/一覧/本文で同じ評価を使い、保存製品に依存せず試験できる |
| 端末内保存 | IndexedDB、Dexieを参照候補にする | 複数レコードの原子保存、索引、復元点。採用版でtransaction/worker/PWA動作を検証 |
| キャッシュ | Service Workerとアプリ更新の安全地点 | 初回オンライン取得後の作業継続。永久保存保証はしない |
| optional cloud adapter | Supabase Auth / PostgreSQL / private Storage | 認証・membership・RLS・revision更新を別層へ。完成版同期を実装するが、接続先と費用は別途具体化 |
| 図 | 種類付き関係データからの描画adapter | ライブラリの図データを正本にしない。タップと一覧で同等編集。ライセンス/サイズは選定時に検証 |
| 検査 | 型/単体/統合/ブラウザー/実端末・権限・障害注入 | 受入試験の正常と失敗を両方確認。文書検査と分ける |
| 公開候補 | 静的Webホスト、基底パスを構成値にする | GitHub Pagesならリポジトリサブパスを扱う。公開先は未作成 |

クラウドadapterが未設定でもローカル編集・専用出力を使える。これを同期要件の削除とはしない。WP17で接続先・認証・容量・費用と権限を具体化し、同期要件を完成させる。既存の別用途バックエンドは使わない。

未確定は技術選定・運用先であり、F01–F60の要件を省く根拠ではない。規範案の変更は仕様差分と影響要件・試験を添える。ユーザーに不要な確認を繰り返さず、既に指示された文書/実装の可逆な作業は進める。

## 公式資料による確認範囲

2026-10-05にReact、Vite、Dexie、WebKit、W3C、RFC、JSON SchemaとSupabaseの公式資料を確認した。[資料一覧](../research/SOURCES.md)のT01以降を参照。参照候補は公式機能の存在からの設計提案で、package版を実機検証した結果ではない。

Supabaseの `changelog.md` は検索取得でContent-Type未対応、HTML変更履歴はタイムアウトとなった。RLSとStorageの現在の公式ドキュメントは取得できた。このPRではSDK版・migrationを確定しない。WP17の開始時に変更履歴とbreaking changesを再確認し、その時点の対応版を固定する。

GitHub Pagesのリポジトリ公開ではViteのbaseを `/shinariokanri/` として検証する。別ホストroot公開なら `/` を使う。route、素材、Service Worker、直リンクを同じbaseへ揃え、previewサーバーを本番運用サーバーとして使わない。現時点でワークフローや設定は変更しない。
