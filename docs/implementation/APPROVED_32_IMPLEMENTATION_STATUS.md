## 保存と失敗時の扱い

過去の契約で固定された `src/domain/schema.json` は原本を保持し、現行の任意項目を含むJSON Schemaは `src/domain/schema-current.json` へ別に生成する。既存345項目・43種類の意味と制約は保持し、承認した7項目の任意追加だけを許す回帰検査を行う。

動画台本、試読修正、回帰期待値、受領指摘と確認時本文は任意の型付き項目で、完全保存の必須機能宣言も追加した。未知の必須機能は保存前に拒否する。過去稿・固定世界・復旧記録を含めて機能を検出し、複製時には確認時だけ存在した段落の識別子も写し替える。新項目のない旧形式も引き続き読み込める。

| 保存する内容 | 必須機能宣言 |
| --- | --- |
| 動画の行種・行番号・元段落 | `video-script-v1` |
| 試読から開いた修正元 | `trial-correction-v1` |
| 作者が指定した回帰期待値 | `regression-expectation-v1` |
| 受領時の前後文と現稿の照合先 | `received-review-match-v1` |
| 確認時の本文と古い照合位置 | `received-review-match-observation-v1` |

翻訳は既存のlocalization、素材の任意の確認メタデータとTwee原文は既存のcustomValuesを使う。一括変更は元版・差分を確認して既存の一回の保存へ渡し、保存中の競合や容量不足では全体を変更しない。素材の許諾根拠やTwee原文は読者用出力へ入れない。Tweeの取消は不変の版履歴を保持しつつ別案の最初の版へ戻す。

製品変更は工程ごとのコミットで戻せる。新機能を保存した作品は対応する版で素材を含む控えを確保し、旧版で上書きしない。一括操作の取消・操作前の復元点・別コピーへの試し復元を使って内容を照合する。

操作手順は[アプリ内マニュアル](../../src/manuals/content.ts)に追記した。既存の文書と正式受入手順は[計画書の検証節](approved-32-improvements-2026-11-07.md#verification)を参照する。
