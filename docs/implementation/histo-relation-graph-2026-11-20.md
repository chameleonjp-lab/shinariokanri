## 1. 目的、正本、範囲

[HISTOの年表](https://history-study-notebook.rksgcl.chatgpt.site/#timeline) は四方向・系統色・破線・説明を参考にする。「中国史の前後」と「比較」が同じ座標を通る弱点は継承しない。配色・コード・教材はコピーしない。採用32案の [計画](approved-32-improvements-2026-11-07.md) と [確認状況](APPROVED_32_IMPLEMENTATION_STATUS.md) は別の正本。02/05/12〜16/31を再利用（本文入口、時刻、分岐理由、読者への提示、提示順、場面移動）、28の入出力を壊さない。既存のAC/RB・正式受入の上書きや完了繰上げはしない。

## 2. 正本からの投影とID

現行 [relationGraph.ts](../../src/domain/relationGraph.ts) は採否、方向、根拠、成立判定を持つが権限境界ではない。[Relationships.tsx](../../src/ui/Relationships.tsx) は共通色・端点間の直線。ページ内に両端がある線だけを描き、全体の孤立項目は出ない。既存の行表、座標移動、保存ビュー、インスペクタ入口は後方互換を要する。

実装時に `src/domain/relationPresentation.ts` を新設し、既存エンジンとUI間の純粋関数 `buildRelationPresentation(input, context)` に分離する。入力は**すでに閲覧可能なデータのみ**で、作者のローカル＋許可された固定版参照か、既存 [createProjection](../../src/domain/projection.ts) の明示的な許可投影かを区別する。後者は成功時の `.projection` のみ（`idMap/omissions/issues` は正本のID等を含み渡さない）。後者は既存非退行試験用の入力境界であり、今回の新画面は作者のみ。既存公開用の投影出力は同じ入力に対して不変とする。公開用ラベルから内部の述語を復元せず、後者から表現できない派生は作らない。元の全量ProjectDataから表示直前に隠す方式は禁止。端点が見えない線は候補・検索・数・束・履歴・戻り先・ツールチップ・アクセシビリティツリーに含めない。閲覧可能な線でも根拠が権限外なら「表示可能な根拠なし」。欠落数に権限外を混ぜない。固定世界は読み取り専用・版IDあり。元データがlocal優先で同IDを解決する現行契約は変更しない。一意に由来を解決できない記録は両版を混ぜず、選択した版の表示対象外／作者側の再確認とする。

## 4. 状態、時刻、本文に戻るルール

- **状態文脈。** [stateUsage.ts](../../src/domain/stateUsage.ts) の read/update/reset と既存の条件評価を使う。演算が取れない旧参照は「更新（方式未確認）」、更新元不明は「出典未確認」。AND/OR/NOTの木構造、葉ごとの型・値・理由を保ち、既存の三値結果を最終判断とする。優先順は①選択版・時間範囲・明示経路からの適用外→「範囲外」、②適用可で既存条件が false→「不成立」、③値や比較根拠が不足→「不明」、④判定の根拠が揃い true→「成立」。試読経路未選択・未走行は別軸「未探索」で、条件や世界状態が false とはしない。既存評価が false でも、時刻/提示/経路の理由を型付きの個別判定として確定できない場合は表示上「理由未確認」、既存結果は詳細に保持。トレース表示のために再実行や効果適用を呼ばない。未知値を false に置換しない。地名の選択で値を書き換えない。
- **時刻。** 作中時系列＝既存の解決済み時間、原稿提示順＝章/場面の著者順、試読順＝選択した実行記録（選択がなければ不明）の専用切替。範囲は半開区間 [start,end)、瞬間は点。Tickは既存比較器の文字列/BigIntを使用し、Number/Dateへの丸めは禁止。相対・暦換算は既存の解決器に従い、循環・欠落・未確定は不明。初版は、比較可能な同一時間軸が構造化データで確認でき、正本の `same_start` 制約がこの2件を直接結び、解決した開始点が確定かつ一致する場合だけ「同じ頃（確定）」とする。暦IDのみ・便宜値・警告のある解決では不可。同一時間軸を明示できる入力が現行にない作品では確定・可能性の新規線は生成せず、「比較根拠未確認」を詳細に表示する。構造化された比較軸がある場合でも概算範囲だけの交差は「可能性」。明示同期を新規編集する型は別仕様。換算なし別暦・参考配置と分かる記録・比較根拠不足は「同期未確認」。暦ID一致だけで確定しない。凪の捜索刻 −1 と故郷再会刻 231 の便宜値から、故郷での経過時間も計算しない。自然言語のメモ解析で分類しない。[教材](../../src/domain/adventureSampleWorld.ts)・[再会](../../src/domain/adventureSampleStory.ts)。
- **選択→本文→戻る。** 起点、選択ノード、選択線、現在フォーカスは別状態。線を選ぶと読み取り専用詳細（名称＋両端＋方向＋適用版/時点/経路/視点＋根拠と粒度）を開く。「本文を開く」は02の入口を使い、画面遷移前に同じ版の表示スナップショットをセッションメモリに保存。戻ると線・フィルタ・ズーム・スクロール・フォーカスを復元。閲覧権を失った場合はスナップショットを破棄し、残存の起点または初期表示へ。線を読むクリック・Enterは編集保存を発生させない。既存の明示「編集」は作者のみ、参照元が固定版なら読み取りのみ。未保存本文は既存ガードの手順を踏む。
- **成立の初期表示。** 全体初期は対象版の記録上の構造を表示し、特定時点を選ばない。不明は表示すると明示。特定時点/経路を選んだ場合も「構造込み」か「成立のみ」を可視ラベルで区別し、切替後の分母を混ぜない。設定の保存は端末の表示設定だけ。旧画面の `useRelationView` と保存キーを共有せず、権限縮小・版切替時に旧キーのfilter/lastOpenedIdを継承しない。遅延の復帰・pagehide・後着レスポンスも世代とキーの一致を再確認し、旧世代を保存しない。既存の明示保存ビューは従来の別操作として維持。

## 5. 展開・集約アルゴリズム

| モード | 入力と制約 |
|---|---|
| 局所 | 初期は起点1つ。既存の深さ選択は互換用に保持し、新探索の既定では各方向ごとに6件ずつ。残りを明示し、「さらに表示」で次の6件。同じ対称線を左右で開いても1ID、自己参照は独立の輪で1回だけ描く。対象候補を述語優先順（因果→条件→伏線→人物→物品→世界→参照）、同順位は確定できる表示順・日本語名・安定IDの順にし、比較不能の日時は末尾の別枠。折りたたみは起点から到達できる残りの展開に基づき再計算。 |
| 連結範囲 | 現在の許可・系統・成立フィルタで起点から隣接をたどった成分。到達判定は両方向、矢印を変えない。走査済みノード・エッジ集合を再利用し O(V+E)。起点が孤立しても1件。 |
| 作品全体 | 許可済み・採用状態で同じ版スコープ内の孤立・複数成分も対象。成立や種類で隠しているのか、画面外か、縮尺で集約中かを別表示。固定世界は明示された読み取り範囲だけ含め、別作品を全量取得しない。 |

モード切替は「局所探索」「つながる範囲を全部」「作品全体」の3つを同じツールバーに常設。起点未選択なら局所/連結は起点を案内し、「作品全体」は選択可能。

局所展開は `(起点側のnodeKey, relationFamily, incoming/outgoing/both)` ごとの展開意図＋展開上限を保持し、起点から到達する枝の和集合で表示する。別枝が保持しているノードと辺は一枝を閉じても消さない。R→A/B、A/B→C の合流・A→B→Aと同端点の複数edgeで確認。視点移動はSVGの表示上のみ。キーボードとモバイルの関係一覧でも同じノード/エッジへ到達。

全体図では章/地域を併記可能でも、描画上の所属は一つ。場面と明示所属エンティティは章、場所は明示地域、未所属は「その他」、同値の場合は安定ID順。境界跨ぎは集約線または表示中の端点から外側の相手を選ぶ接続表示。対象の線を全ページから消さない。束を選ぶと両端の対象・関係ID・述語・出典を検索できる仮想化一覧を表示。任意の1件を選ぶとその両端と線を局所表示へ昇格し、巨大な「その他」からも描画予算を超えず到達。集約対象数、表示中カード件数、束に含まれるエッジ総数、フィルタ限定範囲の分母を分ける。表示更新で選択位置を自動で飛ばさない。暫定詳細描画予算は80カード/160個別線（超過分は束または透過的な一覧に残す）。100本のハブ、孤立、縮尺2段、スマホ縦・横・拡大、VoiceOverでも対象に到達できること。読み上げ名は全文の端点と述語、色なしでも同じ操作。

## 8. 検査コマンド、証拠、リリース境界

**計画PR**：Markdown構文・相対パス・QA IDの対応と差分1ファイルを読戻し。現行 [CI](../../.github/workflows/ci.yml) が選ぶ文書チェック結果を確認。製品テストがCIでスキップされても製品合格とは言わない。

**実装PRの各固定SHA**：リポジトリのNode版で `npm ci`、`npm run check:docs`、`npm run check:completion-plan`。対象ユニットは `npm test -- <対象ファイル>`、統合では `npm test -- --maxWorkers=1 --fileParallelism=false` と `npm run build`。新しいE2Eを既存inventoryへ載せ、Chromium／WebKitの `npm run test:e2e -- --project=<engine>` と現行の該当RBを省略しない。ローカルで動かせなければ実行不能と理由を記録。CIは実行ID、候補のSHA、エンジン、テスト名、失敗・skip・採取した証拠を一致させる。単独smokeや別SHAの成功を移植しない。iPhone 17 Pro Safari実機（縦/短縦/横、VoiceOver、ピンチ、本文の戻り）、ローカル試作、CI、作者比較、配備後を別ステータスで扱う。

[Pages](../../.github/workflows/pages.yml) はmain更新で自動配備する独立ワークフローで、検証完了を待つ設定ではない。計画のDraft PRはアプリ配備の実行ではないが、計画を含むmain更新で既存のPagesフローが動きうる。実装のDraft PRは同一候補の検証完了後に、公開影響を明記して本人のマージ・公開判断へ。こちらからマージ、直push、配備・ランキング・実データ操作はしない。差し戻す場合も既存コードを上書きせず、該当工程の差分を本人判断で戻し、直前正常版と実データを保全。

### 全工程共通の停止基準

他担当を書込み対象に重ねない。最新版mainに差分がある場合は上記の正本・CI・契約箇所の差分を確認し、受入結果をそのまま転用しない。重大不一致（誤表示・データ変更・漏えい・復元不能・色だけでしか読めない・境界線消失）ではマージ候補にしない。修正後に同じfixtureを再実行してレビューへ戻す。要件にない意味や順序を勝手に埋めず、文書の決定表を更新してから実装を進める。
