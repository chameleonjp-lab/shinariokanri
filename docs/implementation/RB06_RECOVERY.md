# RB06 完全保存・任意履歴・明示ID対応復元

対象は REQ-B12/B23/F35/N06/N09/N11/N14、関連AT-E07/E12、RV16/RV17。原要件・受入条件と旧設計レジストリを維持する。下記の実装・局所検査と、実機Files、更新、長時間、全受入の最終判定を区別する。

## 保存と復元の整合単位

端末DBの一つの読取トランザクションから現在内容、全履歴の記録、送信待ち、保留復元操作、確定サーバーrevision、固定世界を取得する。履歴差分の再構成とhash計算はトランザクションの外で行い、後の保存を読み足さない。素材は不変hashで取得する。出力中の別保存は通常保存を完了でき、出力には取得時点の整合した内容・履歴・操作だけを含める。

完全ファイルへ全kind、段落/台詞ID、条件・効果、固定世界の推移依存、作者別案と採用記録、公開snapshot、復元履歴、取得済み素材bytesを保持する。素材を除くファイルは不足を明示し、完全保存済みとは表示しない。未知版・必須機能・破損hash・参照・危険パス・量超過・取消・容量不足は確定前に拒否する。復元の内容・履歴・素材・世界・送信待ち・読み込み前復元点は同じ原子確定へ渡す。

元FILE_FORMATの運用情報除外に対し、今回明示された送信待ちの往復条件を `portable-recovery-v1` 必須機能として追加する。`data/recovery.json` の全bytesはmanifestで列挙・hash検査し、操作の順序、内容hash、元作品/操作/サーバー版を保持する。認証情報・membership・端末識別子・送信権限は保存しない。復元した元操作は `needs_reconnect` として隔離し、接続先・確定基底・権限を検証するまで送信しない。通常の新しいローカル保存操作と件数を分ける。復元はサーバー受領済みの宣言ではない。

## 通常画面と確認基底

既存の新規・clone・同一作品置換/統合を保持する。「別作品へ明示ID対応で統合」ではprojectを含む全ローカルIDの一対一対応と、同ID差分の採用を要求する。名前一致では統合しない。固定世界snapshotのID/hashは不変。元の作者案の版と採用証跡を保ち、移した履歴に元作品/操作と今回の取り込み操作を記録する。自由文内のID文字列は書換えない。

確認時の入力・元ファイルhash・対象revision・ID対応・採用選択・差分・素材をhashで固定する。更新後は入力を残して再確認を要求する。二重保存は停止し、保存したrevisionがpropsへ現れてから完了表示する。画面移動・作品切替で後の選択を無断で開き直さない。元ファイルbytesとID対応/採用入力は端末へ保存し、再起動後も再開できる。承認そのものは持ち越さず再確認する。

履歴の一覧は30件/頁、検索は理由・版・操作ID・対象ID・日時を全記録に適用する。選んだ操作の変更前/後を読み、「この情報だけ」と「作品全体」の復元を分ける。公開不変版、既存作者案/採用記録、全履歴を保持し、新しい補償変更として保存する。移行/読み込み前の復元点も頁で選んで差分を確認できる。確認後のrevision更新や差分改変は保存を拒否する。
