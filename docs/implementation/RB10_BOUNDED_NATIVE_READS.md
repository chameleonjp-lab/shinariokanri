# 全件の冷読込と保存待ちの保護

C25（commit `4fb3cdc0bf57a61223cd772ecf95270c5b864122`）の実Large30回では、起動p95 `10331.40000000596 ms` が元の `10000 ms` を超えた。検索p95 `1431.0999999940395 ms` は元の `2000 ms` 以内だった。起動の不合格raw・判定を保存し、別のコード候補C26で再測定する。C25のStandard30回や過去C24の成功をC26へ付け替えない。

冷読込では取得単位を4096件から8192件へ変える。全範囲を最後まで取得し、作品headerのID順に戻す。作品・情報・関係・段落・snapshot・表示状態を同じ読み込みトランザクションで観測する。Dexieの分割記録middleware、構造・固定世界・hash・整合性の検査と、元のファイル形式・上限を維持する。完全履歴の読込はC25のWorkerによる検査を引き継ぐ。取得単位の変更は性能合格の証拠ではなく、同一最終commit／buildでの再測定が必要である。

保存行のID・種別と本文側のID・種別、段落の保存行IDと段落IDが異なる場合は読み込みを拒否する。情報の本文が別作品を指す場合も拒否する。不一致や不足を現在の有効情報として表示せず、保存済みデータを保持したまま完全保存ファイルからの復元を案内する。古い正当な公開本文コピーは同じIDを保つため、従来どおり読み込める。

読込開始時にsignal・表示方式・進捗callbackを捕捉する。後からoptions.signalが差し替わっても元のsignalを保持し、別signalの取消を読込失敗の説明に借用しない。明示的に取り消した読込では捕捉したsignalを確認し、Native transactionの中断が一般の保存失敗に変わる競合でも `CANCELLED` を返す。取消していない未知のエラーは取消として扱わない。8191／8192／8193件の正確なID・Unicode本文・全履歴、最初の取得後の取消と同一transaction、後半の欠損・別作品・ID・種別・段落ID・分割hash破損、取消・拒否後の全保存表不変をfake-indexeddbを用いる部品検査で確認する。既存4097件の正本文・別scope・取消・後半破損・修復・Native表不変の検査と120秒上限を保持する。

通常画面の保存では、enqueue時に実行待ちの数を同期的に保持し、成功・失敗・取消のfinallyで減らす。章順の直接保存も離脱時の未保存案内に含め、最後の操作が終わるまで保護する。二つの章の保存を実SHA待機で重ねるブラウザー検査は、待機中の離脱handler、両方の原子保存、cold再読込、完全保存の全順序・段落ID・Unicode本文・履歴を確認する。Linuxブラウザーでのhandler検査を実端末の離脱dialog確認へ換算しない。

C25のGitHub CI run `38048314501`／job `114202212093` はunitとbuildが成功し、通常画面の3件が失敗した。実ログ・画面・traceを保持する。作品復元の検査は、復元ボタンの消失による保存版反映を確認してから次の操作と容量拒否を行う。章順の検査は保存済みprops由来の場面番号を確認してから画面移動・再読込する。元の入力保持・全保存表不変・完全保存の全順序期待とtimeout／retryを維持する。先行処理が失敗注入を消費したという推測は、注入callの実観測がない限り確定原因として記録しない。

準備時の失敗も区別して保持する。初回追加9件は実行前の入力捕捉がなく、正式受入証拠ではない。自作取消observerをDBのopen後に登録したこと、close後に再openを忘れたこと、noteへ未定義aliasesを追加したこと、note.kindの型絞り込みを欠いたことは検査設定の誤りとして訂正した。8193件へ拡大した既存単体が120秒を超えた試行は不合格のまま残し、元の4097件と制限を保持し、新境界は追加検査で確認する。

対応はRB06／RB10、RV16／RV17／RV27／RV29と、原REQ-B23・F35・N04・N06・N09・N18・N20／各ATの検証補助である。部品検査の成功を個別AT全句や全116受入の合格へ換算しない。同一最終候補の性能30回、元3保存形式180回、空環境の実ファイル復元、実7200秒、独立全句検査と、実端末・支援技術・専用実Auth／RLS／private Storageの条件は別々に判定する。release evidence gateを緩和せず、マージ・本番公開・課金・外部DB変更を本作業から実行しない。
