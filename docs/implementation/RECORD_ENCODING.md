# 完全保存の共有辞書と必須機能

専用package/正本の形式版とminimumReaderVersionは1.0.0を維持する。原JSON/素材bytes/件数/参照/深さ/500,000構造/64 MiB JSON等の上限を維持する。未知の必須機能を宣言したファイルは、従来どおりmanifestの検査でFORMAT_UNSUPPORTEDとして停止する。

`shared-records-v1` は記録と順序付き配列を辞書で共有する既存の符号化である。大容量の113履歴と送信待ちを保持すると、同じ記録の小さな改稿と各履歴にある暦の重複が、既存の構造数上限に達する。この重複を保存時の符号化で減らし、復号後の全値・全順序・command SHAを保持する。

| 必須機能 | 保存する表現 | 復号時の規則 |
| --- | --- | --- |
| `shared-record-deltas-v1` | `data/records.json` の記録に `__recordBase` と変更したown field、必要な場合だけ `__recordDelete` を保存 | baseは同じ辞書の前方にある記録のみ。全own fieldを継承し、明示した変更と削除だけを適用。削除の重複・欠落field・設定と削除の二重指定を拒否。復号した完全記録を既存schema/ID/参照/hash検査へ渡す |
| `shared-calendar-records-v1` | 同じ辞書へ暦定義を保存し、既存の順序付き配列参照で各履歴の暦を共有 | 暦のID・名称・kind・原点・tick/年/月の全値を保持。既存の暦検査と原参照/深さ上限を適用 |

両機能は `shared-records-v1` と実際に使用した場合の必須機能宣言を必要とする。従来の辞書ファイルは追加機能を有効にせず読み込む。新しい宣言を知らない旧readerは、画像や記録を解釈する前に拒否する。復元時は元ファイルを保持して対応するアプリを使う。

差分の基底はtyped IDで候補を探すが、全fieldの正規JSONを比較して決定する。IDや既存digestだけで同一とみなさない。作者の値に同じmarker fieldがある場合は完全な記録として保持し、制御用markerへ読み替えない。基底への参照も従来の展開参照上限へ算入し、復号後の構造深さと未使用辞書の検査を維持する。

この変更は既存内容の保存表現を圧縮する。追加X01〜X12の正本項目や1.1.0への移行を採用するものではない。生成データでの構造数確認と元のLarge受入は別に記録する。
