## 最初の依頼

この計画PRをユーザーが確認・mergeした後、[依頼用プロンプト](PROMPTS.md)の **1A** をCodexへ貼り付けてください。その後も1単位ずつ依頼します。各単位の終了時に、Codexが次に使う依頼文を引継ぎへ残します。

| 段階 | 依頼単位 | その段階でそろえるもの |
| --- | --- | --- |
| 1 比較基準と検証の準備 | 1A → 1B・1C → 1D | 変更前の実測、足りない証拠の取得手順、制作工程の接続、改善設計 |
| 2 小さな改善の比較・実装 | 2A → 2B → 2C | 履歴、保存、検索、一画面の読込、世界データの保持を順に比較・改善 |
| 3 最終検査と引渡し | 3A → 3B → 3C | CI準備の比較、同一候補での正式受入、証拠の再取得と逐条判定 |

「3段階」は管理上の区切りです。1回の依頼で3段階すべてを実装する運用にはしません。10単位も必ず10 PRになるという意味ではなく、独立した変更や中断があれば同じ単位を小PRに分けます。

## Codexが毎回読むもの

1. リポジトリの [AGENTS.md](../../../AGENTS.md)、このREADME、[守る条件](GUARDRAILS.md)、[段階の進捗](STATUS.md)。
2. 指定された `requests/<単位ID>.md` と、存在する自分・依存元の `handoffs/<単位ID>.md`。
3. 依頼書に指定した原資料の節、対象コード、必要な検査。まず `rg` で呼出元と範囲を特定する。

全履歴、全ソース、全生ログ、すべての依頼書を毎回読み直す必要はありません。必要条件や引継ぎが欠けていれば、その根拠だけ原典へ戻ります。要約だけを検査証拠の代用にはしません。
