# 3A：検査条件を保ってCIの準備時間を比較する

[全体計画](../PLAN.md)／[守る条件](../GUARDRAILS.md)／[依頼文](../PROMPTS.md)

**対応：** NP15。この依頼書の指定範囲だけを進める。

**開始条件：** 2Cで段階2の必要成果がmainへ統合済み。`handoffs/2C.md` と現在のworkflow／CI結果を確認する。

**目的：** 元の検査と証拠の完全性を保ちながら、CI準備の重複を減らす価値を確かめる。

**構成：** まず依存とbrowser準備cacheを比較する。build共有／shardは別案として、候補・配信bytes・各engine・attemptを結べる場合だけ採否判断する。

**技術・仕様：** 既存React / TypeScript / Dexie、Vitest、Playwright 3 engines、Python、GitHub Actionsの対象部分を使う。原仕様は共通条件G01〜G06と原PR #59を維持し、新しい依存追加は実測と必要性を判断する。

## 所有する変更範囲と並行作業

CI担当はworkflow／準備だけ。独立担当はscopeと証拠契約のレビュー。製品sourceの並行変更は止め、採用変更の統合後に3Bへ候補を渡す。#73で導入済みのAGENTS／RTKガイドは維持する。RTKの再導入や正式CIへの組込み作業にしない。

## NP15：CI時間を検査維持のまま短縮する

- [ ] **具体対応：** 現在の7job/3engine成功を対照に、依存・browser準備cacheの効果を先に計測する。必要ならbuild共有やshardを別案比較し、証拠のcommit/tree/build/attempt対応を保つ。#73で導入された任意RTKガイドはローカル出力の補助であり、元CIの準備改善とは分ける。
- [ ] **完了条件：** 全元test・assert・3engine・異常系・添付回収・最終verifyを維持し、経過時間とrunner総使用時間を区別して純効果を示す。cache欠損/破損、partial artifact、別tree、retry混入は拒否する。
- [ ] 純Markdownだけの限定scopeは既存。検査skip拡大、timeout/retry変更、3engine削減で時間を作らない。
- [ ] 同一build共有案は配布bytesの封印・各engineの使用bytes・全inventory照合を証明できなければ不採用にする。

**対象path（既存は入口、新規案は実装時に作成）：**

- `.github/workflows/ci.yml`
- `scripts/ci/（既存scope/証拠検査を確認して対象限定）`
- `docs/acceptance/phase3/VERIFICATION.md`

**戻し方：** workflowの準備方式だけを戻し、原検査・証拠回収の定義を保つ。

### CIを短くする判断

- [ ] 現在の全test／3engine／添付回収／verifyと経過時間・runner総時間を基準にする。2つの時間を混同しない。
- [ ] 現行＋少なくとも2案を比較する。cold／warm、cache欠損・破損を含め、純効果がある準備方式だけ採用する。
- [ ] 同一build共有やshardを比較するなら、配布された実bytesと各engineが使用したbytes、全inventory、attemptの一致を確認する。できなければ不採用とする。
- [ ] docs scopeは既存の保守的判定を維持する。製品／JSON／fixture／runnerのskip拡大、timeout／retry／engine削減をしない。
- [ ] 元CIを実行し、採用変更があればユーザーmerge後のmainで3Bのcandidateを固定する。最新AGENTSと#73のSkillの使用範囲を守り、RTK自己検査を元CIの代用にしない。

## この依頼の検査と終了条件

**検査：** workflow対象の既存CI helper tests、欠損／破損cache、partial artifact／別tree／retry混入の拒否、元全unit／build／3engineと最終verifyを確認する。見かけのjob成功ではなく全inventoryと添付の契約を照合する。

**終了条件：** 準備方式の比較と採否、経過時間／runner総時間、原検査・証拠条件を保持した実CI結果がある。改善なしなら現行を保持して3Bへ進む。

- [ ] 誤動作・誤判定の独立期待を先に確定し、変更に必要な反例で失敗を確認してから修正・再確認する。比較だけの案は入力と期待を固定して採否を記録する。
- [ ] 実行コマンド・exit・対象commit / tree / build・fixture・CI run / attempt・原本path / SHAを保存する。原CIと正式受入を別に記録する。
- [ ] 指定単位の成果をレビュー可能なDraft PRへ提出し、必要CIを確認する。ユーザー以外はmerge・公開しない。
- [ ] [引継ぎテンプレート](../HANDOFF_TEMPLATE.md)を使い `handoffs/3A.md` に完了区間・残区間・採否・阻害・次の一操作を残す。PR提出時は統合待ちとする。中断しても別単位へ進めず、この単位の残りから再開できるようにする。
