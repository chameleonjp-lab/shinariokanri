# 2C：一画面の必要分読込と世界データの保持を比較する

[全体計画](../PLAN.md)／[守る条件](../GUARDRAILS.md)／[依頼文](../PROMPTS.md)

**対応：** NP12 → NP14。この依頼書の指定範囲だけを進める。

**開始条件：** 2A・2Bの必要成果がmainへ統合済み。`handoffs/2A.md` と `handoffs/2B.md`、1Dで選んだ一画面の設計を確認する。

**目的：** まず一画面の読込を限定する価値を実証し、その所有・寿命を保って世界依存と保持方針を比較する。

**構成：** 完全ProjectDataとは別型のread modelを導入し、表示中の依存closureと完全保存のcaptureを分ける。cacheは正本にせず消しても正しさが変わらない構成を維持する。

**技術・仕様：** 既存React / TypeScript / Dexie、Vitest、Playwright 3 engines、Python、GitHub Actionsの対象部分を使う。原仕様は共通条件G01〜G06と原PR #59を維持し、新しい依存追加は実測と必要性を判断する。

## 所有する変更範囲と並行作業

store / App / 共有型の実装は1人。別担当は独立期待、画面外欠損／遅延返却のレビュー、NP14の比較設計を担当できる。NP12の採用境界確定後にNP14を同じ操作列で比較する。

## NP12：一画面から必要分の読込を導入する

- [ ] **具体対応：** 選択章または人物の一画面を選び、依存先だけのread modelを追加する。未読/読込中/読込済み/不在/errorを別型にし、部分値を完全ProjectDataへ偽装しない。必要時に完全読込へ戻せる構成で比較する。
- [ ] **完了条件：** 表示中の根と依存先の正確なID/版/参照が全件結果と一致し、未読を削除や参照切れとして表示しない。遅延応答・account/role切替・取消時に混入しない。完全保存/全文検索/全量検査は独立した完全captureを維持する。
- [ ] 同名別ID、循環、未読依存、欠損、固定世界版、別作品/別account、同revisionのheader変更、store close/reopen、未保存本文、画面切替の遅延返却を検証する。未読を空配列としてsaveProjectに渡したときは型/実行境界で拒否する。
- [ ] Large一画面で読込行数/bytes/保持量と待ち時間を比較する。追加全captureが毎操作を遅くするなら対象を狭めるか不採用にする。

## NP14：共通世界と保持量の上限を確かめる

- [ ] **具体対応：** 選択作品の世界依存走査、whole row取得、未知owner時fallback、inactive cacheの保持/再読込を分離計測する。4件・8件・16件・bytes基準の案を同じ操作列で比較し、必要なら寿命/配分を調整する。
- [ ] **完了条件：** 論理graph数、payload、GC後heap、計測できるpeak、画面待ちを別列で示す。固定世界版/履歴用依存/未保存draft/送信待ちが保護され、cacheを消しても正しさが変わらない。4件保持をアプリ全体のmemory上限とは表現しない。
- [ ] unknown owner、循環、欠損、同hash別版、同ID別hash/別内容、異なるouter rowに保持された同一snapshot IDの衝突、権限取消、draftを保持した切替、遅延ACKを検証する。
- [ ] save tuple捕捉、世代fence、ACK最終transaction guardは既修正の正しさとして保持し、cache方針の比較と一緒に戻さない。

### 選択画面と保存境界

- [ ] 1Dで選んだ一画面だけを対象にする。全画面のpartial化へ広げず、必要依存のID／版／参照を全件結果と照合する。
- [ ] 未読を空配列・欠損・削除と同一視しない。型境界と実行境界で、部分値がsaveProjectへ渡る誤用を拒否する。
- [ ] owner tupleにはaccount／role／project／revisionに加え、world pin project／snapshot／hash、schema、native header fingerprint、store寿命の証明を維持する。
- [ ] NP12が効果不足で不採用でも、その比較結果を閉じた後に現行完全currentを対照としてNP14を進められる。採用していないpartial APIを存在する前提にしない。
- [ ] NP14は4／8／16件とbytes基準を比較する。論理graph数、payload、GC後heap、計測できるpeakとlatencyを別にし、保持件数を総メモリ保証にしない。
- [ ] 採用変更と不採用理由を集約し、第2段階のSTATUSを更新する。必要なPRのユーザーmergeと全CIを確認して3Aへ渡す。

## この依頼の検査と終了条件

**検査：** 未読依存・循環・同名別ID・headerだけ変化・store再生成・role取消・遅延返却・draft保持を全件対照で検証。worldは同ID別hash／内容、同snapshot IDの異outer row衝突、unknown owner、遅延ACKを含める。元全CI・3engineを維持し、Large一画面の読込行数／bytes／待ち／保持量を比較する。

**終了条件：** NP12の一画面と完全保存の境界、NP14の保持比較、各採否と戻し方が実証され、段階2の採用変更が統合済み。全面partial化や全体memory上限を達成したと拡大解釈しない。

- [ ] 実行コマンド・exit・対象commit / tree / build・fixture・CI run / attempt・原本path / SHAを保存する。原CIと正式受入を別に記録する。
- [ ] 指定単位の成果をレビュー可能なDraft PRへ提出し、必要CIを確認する。ユーザー以外はmerge・公開しない。
