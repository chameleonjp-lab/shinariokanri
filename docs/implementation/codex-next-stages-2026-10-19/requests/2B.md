# 2B：保存前処理と検索・一覧の準備を分担して改善する

[全体計画](../PLAN.md)／[守る条件](../GUARDRAILS.md)／[依頼文](../PROMPTS.md)

**対応：** NP11・NP13。この依頼書の指定範囲だけを進める。

**開始条件：** 2Aの必要成果がmainへ統合済み。`handoffs/2A.md` と1Dの比較設計を確認する。

**目的：** 保存と検索という独立した処理の費用を分離測定し、現行契約内の効果がある案だけ採用する。

**構成：** 保存は既存v1/v2 hashとatomic境界を維持して前処理の重複を減らす。検索は正確なID／順序／件数と画面に必要な一致位置の生成を分ける。

**技術・仕様：** 既存React / TypeScript / Dexie、Vitest、Playwright 3 engines、Python、GitHub Actionsの対象部分を使う。原仕様は共通条件G01〜G06と原PR #59を維持し、新しい依存追加は実測と必要性を判断する。

## NP11：保存前の重複処理を減らす

- [ ] **具体対応：** 保存前のrequest hash、normalize、targetChanges、contentDelta、書込差分、summary countの時間・走査・割当を分離計測する。現行と少なくとも2案を比較し、原v1/v2再送bytesを保つ範囲で重複処理を減らす。
- [ ] **完了条件：** 変更recordのみの既存書込、同operationId再送/別request拒否、64復元点、全体検証、原子保存、未保存入力が同じ。原3保存形式×2fixtureの6条件×30と仕事量/保持量で改善を確認する。P2-03の不採用changesetをそのまま復活させない。
- [ ] 入力captureの後にcallerが値を変える反例、同ID別内容、world pin、権限取消、fake ACK、quota、最終transaction失敗、cold再読込を全件対照で確認する。
- [ ] 全量request hashは現行v2契約の費用として残る。少量編集をO(変更量)にするpatch command/新request版は別の契約変更案として保留し、性能だけで採用しない。

## NP13：検索と一覧の準備範囲を絞る

- [ ] **具体対応：** 結果ID・順序・総件数の確定と、画面で必要な本文一致位置の生成を分ける案を比較する。cold/保存直後/予算外の末尾/複数作品を計測し、索引の保持・失効を必要単位へ細分化する価値を判断する。
- [ ] **完了条件：** 0件/少数/大量/末尾一致と先頭/中間/末尾ページで、全件対照のID・順序・件数・Unicode位置に一致する。改名/別名/削除/参照変更、秘密、role取消、予算超過時も正しい。実latencyと保持量が説明できる案だけ採用する。

## この依頼の検査と終了条件

**検査：** NP11は独立save oracleと原6条件×30の180保存比較、再送／別request／world pin／権限撤回／fake ACK／最終transaction失敗／coldを照合。NP13は全件対照のID／順序／総数／Unicode位置／秘密／role／予算外を照合。最後に元全CI・3engineと両者の接続を確認する。

**終了条件：** NP11・NP13の現行＋2案、採用／不採用、速度・仕事量・保持量、原契約／独立期待への一致、局所と統合CIがある。元形式や全量hashの残る費用を隠さない。

- [ ] 誤動作・誤判定の独立期待を先に確定し、変更に必要な反例で失敗を確認してから修正・再確認する。比較だけの案は入力と期待を固定して採否を記録する。
- [ ] 実行コマンド・exit・対象commit / tree / build・fixture・CI run / attempt・原本path / SHAを保存する。原CIと正式受入を別に記録する。
- [ ] 指定単位の成果をレビュー可能なDraft PRへ提出し、必要CIを確認する。ユーザー以外はmerge・公開しない。
- [ ] [引継ぎテンプレート](../HANDOFF_TEMPLATE.md)を使い `handoffs/2B.md` に完了区間・残区間・採否・阻害・次の一操作を残す。PR提出時は統合待ちとする。中断しても別単位へ進めず、この単位の残りから再開できるようにする。
