# RB05 階層・反応系列・型付き途中開始

RV11/RV12の追加実装を記録する。原104要件・116受入・24工程の完成宣言ではない。固定参照／部分上書き、伏線の未回収方針／期限と変更再確認、改訂後の回帰経路再確認、認識比較の全対象条件は引き続き実装対象である。

章→場面→台詞・分岐ノードを掘り下げられる。下位呼出図の未接続出口・不採用台詞・初期条件の未知を、折りたたんだ上位にも集計する。問題から通常フォームを開いて修正すると集計を更新する。構造検査と全経路探索は区別し、入口／出口の宣言を表示する。表示は階層ごと60件、閉じた下位はDOMへ作らず、選択とページを保持する。

「短い反応の系列を作る」は初回／再訪、順次、抽選を既存の条件・訪問数・flow graphへ変換する。場面本文を複製せず共通IDを参照する。順次系列は最終反応を繰り返し、抽選は既存のseed／抽選位置で再現する。通常の巻戻・周回・reset・保存版再生を用いる。作品別下書きは移動／再読込から再開でき、保存待ちの再入でも二重作成を止める。確認したrevisionから作品が進んだ場合は入力を保って再確認を求める。保存失敗でも入力を保つ。

「途中開始の状態を作成」はhash検証済みの固定版とcheckpointを一操作で保存し、通常の型付きフォームへ開く。状態値・所持品・人物の認識などを編集し、その固定版を開始対象にする。借用世界の情報は正本へ複製しない。保存待ち・失敗・開始点は作品別に保持して画面へ戻った際に再開する。任意の途中状態は`partial`であり、作者が`full_play`ラベルへ書き換えても、宣言入口の初期提示状態と一致しなければ途中開始へ戻す。

回帰確認は固定版・開始状態・全経路の一致に加え、実行が終端まで完了し、提示条件が未知でないことを要求する。未知の初期開示や未完の経路をラベルだけで確認済みにしない。`stub`／途中開始／章試読の証拠は区別し、実ゲーム結果には受領証跡が必要である。

検査手順は`tests/rb05-structure-reading.test.ts`、`tests/e2e/rb05-structure-reading.spec.ts`を参照。通常フォームの編集→原子保存→再読込→旧固定版試読→巻戻、既存作品のcold start、native復元／cloneとseed再生を別々に検査する。独立レビューで発見した上位集計漏れ、未知経路の確認済み化、遅延Reader再入、履歴tokenを失うcold保存を回帰条件へ取り込んだ。実端末・支援技術と原受入全条件は未実行のまま保持する。
