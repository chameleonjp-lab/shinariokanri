# RB05 提示順・未回収・開始版移行・変更後再確認

原B17/B19、F15/F17/F18/F43〜F47、N19、BEHAVIOR_CONTRACT §6/§8の正常・失敗条件を保持する追加である。原104要件、24工程、116受入、6回帰群の完成宣言ではない。関連する公開出力はRB08、実端末・全性能・実権限・最終受入はRB09/RB10の対象として保持する。

章と分岐の実際の提示記録を共通検査へ渡す。全開示候補の条件を同じ提示効果前の状態で観測し、確定した効果群を原子的に適用する。発言を照合するときは、記録した観測状態から確定した効果を本文・台詞順に発言位置まで再構成する。同場面内の先行取得を後続発言へ反映し、後の取得を前の発言へ遡及しない。観測のない旧記録・不確定順序は未知。作者真実、証言、信念、仮説と人物の取得を分け、理由のある嘘・誤解・引用を別分類する。読み手への提示IDと段階を並べても、読者の理解は認定しない。

人物の認識取得には採用中の出所と本文の取得位置または世界内の取得時点を要求する。未知の取得内容、未到達・順序不明の位置、没出所、期間外、経路不成立は停止する。効果群に金額・物品の更新を含めても全体を拒否する。本文位置・世界内tick・現実期限を同じ型にしない。

今作・続編・意図した未回収・誤誘導・検討中・不採用を区別し、対象作品・章・graph・経路の範囲を保つ。回収を提示しない終端、対象章の終了、graph出口と明示した体験上の提示期限を確認する。段落全体・台詞・Unicodeコードポイント位置で期限前後を比べ、世界日時では代用しない。未知の期限は通常終端の確定評価へ置換しない。必須・代替・別経路の情報、例外の理由・範囲・期限・根拠、証人経路と開始状態を保持する。全宣言入口の有限探索にも同じ評価を用い、途中・stub・未探索を全経路確認へ算入しない。

別版checkpointは通常画面で移行差分を確認して、新しい途中開始へ移行するか対象版の初期値から再作成する。元のcheckpointと固定版を保存したまま、同じ宣言の状態・物品・取得根拠・既読を持ち越す。変更・削除された宣言や本文の記録は外し、算出値は移行した値から再計算する。新規値は対象版の初期値を使う。呼出し途中と一度限りの発火記録は再作成する。型・範囲・相互排他・対象版を検査し、移行した開始を通し確認へ昇格しない。固定再利用の相互排他例外は、元の固定版と使用先のgraph・章・開始場面・世界内tickを含む同じ実行文脈で章試読・分岐・移行を評価する。checkpointへ開始時点を保持し、期限切れは拒否する。旧checkpointに複数の提示時点がある場合は、移行先時点の明示を要求する。移行元と元の版は型付き参照で保存し、native/cloneのID対応へ反映する。

保存した経路の宣言・本文・章順・固定世界版の差分を再確認待ちとして表示する。旧証跡をhash検証して先に再生し、改訂稿の初期値と宣言から同じ操作を実行する。途中開始は移行・再作成した開始状態を明示する。条件不成立・未知・欠落・取消・上限で実行不能なら新しい確認証跡を保存しない。章単位の経路は改訂した章の提示順を明示して再提示する。場面単位で選んだ経路と選択単位のない旧記録は、元の場面範囲・順序を保持し、章全体へ拡大しない。個別章開始値には明示した版移行・再作成を要求する。stubの初期入力を型付き参照で保存し、再確認でも同じ仮値として扱う。入力を復元できない旧stubは開始状態の移行・再作成を要求する。個別途中状態へstubを重ねた場合は、元の型付き状態と初期仮値も固定版内で保持する。再生時に入力から開始状態を再構成し、保存した値・外部値と一致しなければ保存・完全保存・再生を拒否する。正当な途中開始＋stubは複製後もstubのまま復元する。新しいcheckpoint・trace・snapshot・reviewと回帰集合への追加を同じ原子保存へ渡す。旧証跡・旧集合の宣言を残し、版・開始由来・stub/actualを区別する。actual/mixedは受領証跡を改めて確認するまで再確認合格にしない。

確認差分と結果のhash、基底revision・開始点・開始場面・世界内tick・読み方を固定して画面に示す。確認後・保存待ち・キュー処理中に作品が変わった場合は保存を拒否し、入力と結果を保持する。同一ターンと保存完了props反映まで操作を直列化し、画面移動からも待ち状態を再開する。失敗では差分を残して再試行できる。保存完了表示は保存したIDと固定版が最新propsに現れた後に出す。

追加検査は `tests/rb05-narrative.test.ts`、独立正期待を保持した `tests/rb05-narrative-boundaries.test.ts`、`tests/rb05-reconfirmation.test.ts`、production通常操作 `tests/e2e/rb05-reconfirmation.spec.ts` に記録する。元の設計レジストリのplanned/not_runを更新して完成扱いにせず、現在の局所結果を別に記録する。

固定借用の対象graph・章も宣言と実行文脈で同じID対応を使う。対象範囲だけの参照と実際に呼び出す子graphを区別し、現在の使用先が元の許可対象なら同じ固定例外を評価する。別のgraph・章への使用は範囲外のまま拒否する。子graphを呼び出したときはその仮想graph IDを保持し、元IDへの一律な巻戻しで内部の限定遷移を拒否しない。`tests/rb05-edition-extra.test.ts` の CTX-graph/CTX-chapter/CTX-child で同一範囲、別範囲、内部呼出し、期間外の原子拒否とnative往復を検査する。
