## A 書き始めと物語の構成

### F01 思いつきを一時置きする

作品内の受け皿へ、短い文章・画像・音声メモを保存する。あとから人物、場面、伏線へ変換し、元のメモも参照できる。

完了の目安: スマートフォンで一文を残し、PCで場面へ変えても元のメモを追える。

区分: 追加 / 基礎。原出典: S13・S22 / 私の提案。対応要件: REQ-F01。

### F02 入力項目と雛形を変える

人物や場面の項目を作品ごとに追加する。必須にする項目、説明文、初期値を選べる。使わない項目や画面を隠す。

完了の目安: 設定を細かくしない作品でも、名前と要約だけで登録を始められる。

区分: 追加 / 基礎。原出典: S06・S12・S19。対応要件: REQ-F02。

### F03 人物以外の筋で並べる

縦軸を人物、組織、場所、章、恋愛や戦争などの物語の筋へ切り替える。一つの場面を複数の筋から参照する。

完了の目安: 場面を別の筋にも表示しても、本文が別々に複製されない。

区分: 拡張 / 主要。原出典: S02・S12。対応要件: REQ-F03。

### F04 場面の役割を記録する

視点、人物の目標、対立、結果、新しく分かること、前後で変わることを短く記録する。役割のない場面も許容する。

完了の目安: 場面を開くと、物語に加える理由と変化を確認できる。

区分: 拡張 / 主要。原出典: S12 / 私の提案。対応要件: REQ-F04。

### F05 構成の雛形と盛り上がりを見る

物語の構成を雛形から選び、自由に変更する。場面の緊張度や重要度を自分で付け、選んだ進行順で偏りを確認する。

完了の目安: 表示は作者が付けた値から作り、作品の良し悪しを自動採点しない。

区分: 追加 / 発展。原出典: S12・S13 / 私の提案。対応要件: REQ-F05。

### F06 要約と本文を行き来する

カードには要約、執筆画面には本文を出す。章や選んだ道を通して読む。要約、本文、作者メモを分け、小説用にはルビ・縦書きの確認表示も用意する。

完了の目安: 作者メモを試し読みへ出さず、本文の修正が関連する表示へ反映される。

区分: 追加 / 主要。原出典: S06・S23・S27 / 私の提案。対応要件: REQ-F06。

## B 時間・人物・地図を結ぶ

生年月日、寿命、状態の変化を出来事と結ぶ。年表で選んだ時点の年齢、存命、所属を表示する。独自暦で計算する。

完了の目安: 死亡後の場面は、回想・記録・復活などの意図を添えて例外扱いできる。

区分: 拡張 / 主要。原出典: S03・S19 / 私の提案。対応要件: REQ-F07。

### F08 時間差と前後関係を守る

完了の目安: 表示の拡大・縮小で日付は変わらず、日付変更の影響を取り消せる。

区分: 拡張 / 主要。原出典: S04。対応要件: REQ-F08。

### F09 一つの世界を複数作品で使う

共通設定を参照しながら、作品ごとの開始時期、採用設定、登場人物、章を管理する。改訂した設定の影響先を一覧にする。

完了の目安: 過去作品の公開時点の設定を保ったまま、続編用の設定を作れる。

区分: 追加 / 発展。原出典: S12 / 私の提案。対応要件: REQ-F09。

### F10 地図と年表を連動する

地図の場所から出来事を絞り、出来事から地図の位置へ移動する。世界→地方→街→建物の地図をつなぐ。

完了の目安: 地図画像がなくても場所の一覧で作業でき、地図を追加しても同じ場所を参照する。

区分: 追加 / 主要。原出典: S13-S15。対応要件: REQ-F10。

### F11 移動と場所の変化を記録する

登録した移動経路、手段、所要時間から時期を確認する。場所の改名、破壊、再建、支配組織の変化も時点で切り替える。

完了の目安: 計算に使う時間が未設定なら、移動不可能と断定せず未確認にする。

区分: 拡張 / 発展。原出典: S15 / 私の提案。対応要件: REQ-F11。

### F12 家系・別名・正体を扱う

家系、師弟、血統などを専用表示にする。同じ人物の本名・偽名を時期と認識者に結び付け、作者向けと公開向けの名前を分ける。

完了の目安: 正体を明かす前の資料に、本名や家系のつながりが表示されない。

区分: 拡張 / 発展。原出典: S17・S20 / 私の提案。対応要件: REQ-F12。

## C ゲームの進行を確認する

### F13 図を章・場面・会話へ分ける

大きな図では章だけを表示し、選ぶと場面、さらに会話へ掘り下げる。小さな図の入口と出口を明示してつなぐ。

完了の目安: 図を折りたたんでも、中に条件や未完成箇所があることを確認できる。

区分: 拡張 / 基礎。原出典: S06・S07。対応要件: REQ-F13。

### F14 発生のきっかけと条件を分ける

場所に入る、話しかける、戦闘に勝つなどのきっかけと、所持品・生存などの条件を別に登録する。一度だけ、繰り返し、期限も扱う。

完了の目安: 前提が成り立つだけで出来事が勝手に起こらず、きっかけが必要か選べる。

区分: 拡張 / 主要。原出典: S06・S19・S28 / 私の提案。対応要件: REQ-F14。

### F15 途中状態から試し読みする

所持品、人物の状態、既読情報などをまとめた開始状態を保存する。そこから試し読みし、選択を戻すと状態も戻す。

完了の目安: 途中開始で必要な状態がない場合、最初から開始した場合と区別して表示する。

区分: 拡張 / 主要。原出典: S08・S25。対応要件: REQ-F15。

### F16 選択前後と別の道を比べる

試し読みの前後で、知識、好感度、所持品など何が変わったかを表示する。同じ場面に到達した別の道の状態とも比べる。

完了の目安: 合流後に差が残る場合、差を消すのか、会話などへ反映するのか確認できる。

区分: 拡張 / 主要。原出典: S05・S08 / 私の提案。対応要件: REQ-F16。

### F17 確認した経路を保存する

選択の履歴と開始状態、作品の版を保存して再実行する。通った場面・選択肢と未確認箇所を一覧にし、変更後の再確認に使う。

完了の目安: 確認できた割合は対象を明記する。場面を見ただけで全条件を確認済みにしない。

区分: 追加 / 主要。原出典: S08・S25 / 私の提案。対応要件: REQ-F17。

### F18 条件と行き止まりを検査する

参照切れ、出られない繰り返し、選択肢の消失、到達できない終わりの候補を調べる。根拠になる条件と経路を添える。

完了の目安: 外部の処理など分からない条件は未確認にする。意図した終わりと進めない不具合を区別する。

区分: 拡張 / 発展。原出典: S06・S28 / S32は公開予定の参考。対応要件: REQ-F18。

## D 再利用・素材・ゲーム制作へ渡す

### F19 共通の会話や場面を再利用する

参照して共通部分を使う、独立した複製を作る、一部だけ変える、を選ぶ。再利用先と変更の影響を一覧にする。

完了の目安: 元を変更するとどこが変わるか分かり、意図しない分岐へ反映されない。

区分: 追加 / 主要。原出典: S07・S28。対応要件: REQ-F19。

### F20 短い反応と周回を扱う

条件で変わる短い台詞、初回と再訪、順番に出す反応、抽選する反応を登録する。周回で残す情報と初期化する情報を選ぶ。

完了の目安: 繰り返しでも重要な情報が失われず、抽選の結果を記録して再現できる。

区分: 追加 / 発展。原出典: S06・S28 / 私の提案。対応要件: REQ-F20。

### F21 台詞に変わらない番号を付ける

台詞と選択肢の一つずつに、表示しない番号を付ける。文章を変更しても翻訳、音声、ゲーム側の参照との対応を保つ。

完了の目安: 並べ替えや改名をしても、別の台詞の音声へ取り違えない。

区分: 追加 / 基礎。原出典: S31。対応要件: REQ-F21。

### F22 演出と必要な素材を結ぶ

話者、表情、立ち絵、背景、音楽、効果音、間、カメラなどを台詞や場面に結ぶ。仮素材・完成素材と不足を確認する。

完了の目安: シナリオだけを読める表示と、演出を含めて確認する表示を切り替えられる。

区分: 追加 / 主要。原出典: S06・S07・S30 / 私の提案。対応要件: REQ-F22。

### F23 翻訳と音声の見直しを管理する

言語ごとの本文と用語、収録メモ、音声を対応させる。元の文章を変えたら翻訳・音声を見直し対象にし、担当別に書き出す。

完了の目安: 元の文章だけが変わっても、古い翻訳や音声を完成済みのまま扱わない。

区分: 追加 / 発展。原出典: S06・S10・S31。対応要件: REQ-F23。

### F24 目的に応じて書き出す

保存用の完全な作品、読みやすい資料、選択して読める簡易体験版、ゲーム制作向けの構造化データを別々に出力する。

完了の目安: 保存用の読み戻しでは情報を保つ。制作・公開用には作者メモや秘密を必要に応じて除く。

区分: 拡張 / 主要。原出典: S06・S11・S26-S29 / 私の提案。対応要件: REQ-F24。

## G フラグ・条件・状態の辞書

### F37 状態の意味と初期値を登録する

状態ごとに表示名、説明、型、初期値、許容値を定める。オン・オフ、数値、選択肢から選ぶ状態を使い分け、関連する人物やクエストと結ぶ。

完了の目安: 「死亡」と「存命」のような反対の意味の値を重複して管理しない。未設定を偽と決め付けない。

区分: 拡張 / 基礎。原出典: S06・S41 / 私の提案。対応要件: REQ-F37。

### F38 有効範囲・初期化・算出を決める

完了の目安: 持ち越す記憶と初期化する所持金を分ける。「好感度が一定以上」を別の値として二重更新しない。

区分: 拡張 / 基礎。原出典: S28・S42 / 私の提案。対応要件: REQ-F38。

### F39 読む箇所・変更箇所・理由を追う

完了の目安: 値が変わった理由から対象の選択や処理へ戻れる。使われていない状態も候補として見つかる。

区分: 拡張 / 主要。原出典: S08・S41 / 私の提案。対応要件: REQ-F39。

完了の目安: 「鍵あり、かつ、昼または夜」の括弧を明示する。今の値で選択肢が出ない理由を説明する。

## H 伏線・情報の開示・文章の基準

### F43 伏線を独立した項目として持つ
