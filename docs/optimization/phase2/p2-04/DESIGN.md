## Comparison before implementation

| Representation | Integrity and work | Decision |
| --- | --- | --- |
| Current complete commands | All header IDs read; all packed body parts decoded and verified; metadata identity checked for every command. Does not reconstruct every before/after. | Keep as fallback and frozen oracle. |
| Derived metadata table | A source fingerprint cannot verify unread parts. Verifying old packed bodies retains their I/O; trusting only a derivative would change legacy failure behavior. | Reject unchecked derivative. No persistent derived table. |
| Canonical metadata plus existing packed body | New heavy command envelopes carry canonical metadata and the existing v1 packed descriptor. Every header ID and every referenced part key is checked; selected/full readers verify complete bodies. | Prototype registered D04 B using existing transactional stores. Adoption requires independent correctness review and measured benefit. |

Only commands already exceeding the unchanged packing threshold receive the new envelope, and only through explicitly bound store writer transactions. Inline commands and pre-existing packed commands keep the original full-reader semantics. Original `historySeries` 100/1000/10000 direct rows remain untouched fallback, not evidence of an all-metadata path. No schema upgrade, eager migration, external native/runtime format change, or new table is needed. Metadata strings can themselves be large; reject the optimization for envelopes exceeding the existing native packing threshold and retain the original packed representation.

## Canonical representation and verification boundary

The commands row retains its existing index fields and `__scenarioRecordParts` descriptor, plus a versioned canonical metadata marker. A SHA-256 seal covers all envelope fields including exact metadata, indexed identities, descriptor/root, scope and part keys/hashes/byte sizes. The complete original command remains losslessly encoded in its original v1 parts. This seal verifies metadata/descriptor correspondence, **not unread body bytes**.

Page reads remain O(N metadata), retain header order, query normalization, bounds and all-ID/project/missing checks, and check existence of every referenced body part using key reads in the same transaction. Missing off-page commands or parts reject. New canonical body bytes remain unloaded: stale/corrupt bytes with intact keys reject at selected-command/full reconstruction/export, through the existing part hashes, graph validation and index correspondence, plus exact canonical metadata equality. Legacy and unknown-version envelopes use complete decoding; malformed recognized metadata rejects. Unknown metadata versions are decoded through the complete body path and rejected; they do not inherit a capability to skip validation. No unchecked marker grants a fast path.

## Writers, readers and atomicity

Normal save, local native ACK command creation, confirmed sync resolution, and imported command batches bind canonical packing. Existing middleware still atomically writes commands and all parts, aborts partial requests, and removes replaced/deleted parts. Direct table fixtures and old databases are not rebound automatically. Readers (`get`, `bulkGet`, indexed queries, filtered cursors), parent reconstruction, replay, outbox and full export continue receiving the exact original command. Only a private, uncached DBCore getMany request asks for metadata. Its unforgeable in-memory object identity is registered for the duration of that one request, with a copied key array. The native transaction is never branded: concurrent get/bulkGet/query/cursor and reading hooks receive complete rows even when nested Dexie transactions share the same parent r/rw transaction. Request cloning by unsupported middleware loses only the optimization. No independent r! transaction is forced inside a parent writer.

Optional rewriting is ordinary full validated read plus bound put in one transaction; it is not performed on opening or paging. Failure/quota retains original rows/parts. No accepted old row is deleted without its original body being retained in the new envelope's parts.

The accepted canonical metadata shape contains strings, a dense string targetIds array, optional string compensation ID, optional string-valued idMap and exact three-string importOrigin. Unknown fields or own undefined values use complete-body fallback on write; a recognized envelope with those shapes rejects on read. Both the envelope metadata and decoded original metadata must pass this shape before canonical JSON equality is used, so omitted undefined cannot hide a mismatch. Original packed values preserve all own undefined properties. Oversized canonical metadata uses the unchanged fallback.

Native header and descriptor shapes are checked exactly. A checksum is not authentication: a coordinated native metadata replacement plus recomputed checksum is a new self-consistent canonical header, and the page displays that metadata. Actual selected/full/export body decoding rejects its mismatch with the preserved body. Cold full reads are explicitly exercised; existing warm project caches are not claimed to revalidate externally mutated native bodies.

## Rollback

Disable metadata reads while retaining the compatible decoder; this reads all command bodies on the unchanged v8 schema. A literal old binary rejects the additional envelope fields and is **not** a rollback adapter. A validated transactional rewrite through the old writer (binding disabled) removes new metadata while preserving all command values; only after every new envelope has been rewritten can the old decoder be used. Test both adapter paths and interrupted rewrite. Never delete or downgrade the database.

## Numeric metric definitions

All metrics are default-OFF, numeric-only, in-memory. `history.header.payloadBytes` estimates the decoded project header, including all history IDs; generic projects/recordParts DB counters additionally expose a packed header's actual body reads. `history.metadata.rows/payloadBytes` count recognized canonical envelopes; `history.legacy.rows/payloadBytes` count every inline or packed fallback envelope exactly once in the private request, before body decoding. Payload bytes use the existing probe's UTF-8 scalar/key and binary estimate and exclude JS/IDB overhead; they are not physical disk or heap measurements. `history.body.rows/partRows/partBytes` count command body decodes and actual fetched part byte lengths, separately from project header parts. `history.partKeys` counts existence checks (including missing keys); `db.read.requested.recordParts` and `db.read.keys.recordParts` distinguish requested/returned keys. These key reads do not contribute body rows/bytes. `hash.calls/bytes` include metadata seals on the main thread; worker-internal hashing and keep-alive reads remain outside the existing probe. All logical history rows are still visited, and all metadata query/order filtering remains unchanged.

Writer-only `history.write.candidates/fallbackShape/fallbackSize/canonical` count attempted packed-command metadata preparation and its outcome. `history.write.sealCalls/sealBytes` count only the writer's actual canonical seal input bytes, excluding page/full-reader verification seals. Counts describe preparation attempts, not commits; generic transaction success/abort counters separately prove persistence. Inline writes never enter candidate preparation. The driver reports inline/packed-fallback/canonical native row proportions and both total hash work and writer seal work; fallback preparation is not treated as zero cost.

Initial failures are retained: missing representation RED, cold-reopen test setup, incorrect inclusion of packed project header parts, clone operation count, deep binary matcher timeouts and test-only spy type error. Resume RED independently exposed transaction capability leakage, own undefined loss and legacy counter undercount. New byte-parity assertions compare lengths, all actual bytes and each part's metadata without a costly generic typed-array matcher; no original or new timeout was increased. No performance/adoption claim precedes independent review and scheduled measurements.

## Independent shape review and native-browser correctness

Review S1 exposed canonical JSON collisions for built-in objects stored as `idMap`; S2 exposed sparse arrays with extra enumerable properties compensating for missing indices. Canonical metadata now admits only plain records (ordinary or null prototype), and target IDs/part descriptors require every own array index with no extra enumerable keys. The shared string-record predicate covers both `idMap` and `importOrigin`. Unsupported writer shapes remain original full-body fallback; recognized malformed native envelopes reject even with a recomputed seal. Independent negatives retain Map/Date/Set/empty typed-array same-digest examples and both sparse-array examples. No serializer or body-read guarantee changed.

The additional `tests/e2e/history-canonical-metadata.spec.ts` uses real HTTP UI import, IndexedDB and normal selected/full-download consumers. Its deterministic two-operation fixture has ten historical notes (nine distinct 500000-byte strings plus a small literal sentinel) and an empty current revision, keeping rendering small while exceeding the production packing threshold. It asserts an actual native version-1 canonical marker, normalized query, selected sentinel body, exact cold full-export history, and intact-key body corruption: metadata page remains available, selected/full reads reject, and native commands/parts remain byte-identical to their post-corruption snapshot. Fixture canonical/archive byte lengths and hashes are attached. This supplemental input does not replace any original scale/acceptance fixture. The new test has its own 120-second UI import/export budget; original tests, configuration and timeouts are untouched.
