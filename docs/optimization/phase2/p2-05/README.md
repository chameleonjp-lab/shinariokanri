# P2-05 dependency and retention checkpoint

Implementation starts from reviewed P204 `5b3949253937f1880bd426b39706c90a1db2e343`. See [design and plan](DESIGN.md). Independent exact-head specification and quality review, the controller's exclusive capture slot, final CI and adoption remain separate gates.

Inactive project graphs use an internal four-entry LRU; project/head/history/completeness collections are removed together. Unique project identities fence late reads without permanent numeric tombstones. Active saves keep their previous image and native history/head tuple from the same read image independently of cache retention. Cancellation after native commit skips only new cache publication; the committed API result and native state stay successful. Weak editing-history tokens and author drafts remain outside the inactive budget.

Known current, save and complete-read roots use complete immutable dependency rows. Explicit editions establish the owner of retained typed snapshots before typed references are resolved. Typed external editions still probe an existing direct outer row, so a conflicting selected copy cannot hide behind a healthy retained copy; a missing direct row with an established retained owner needs no full fallback. Unknown shapes/owners keep full-registry fallback. Pin writers retain their original full validation/global collision checks. Complete export/recovery keeps its complete single native registry capture and original worker closure; selected history keeps P204 materialization. These retained full paths are not O(closure) claims. Applied ACKs with incoming world rows repeat the global retained-ID guard inside the final native write transaction. The existing early guard preserves fail-fast/error ordering and replay/conflict paths; the added full scan for nonempty applied input has unmeasured cost.

App separates adopted dependency graphs from one replaceable preview owned by editor ID, revision and committed selection generation. The latest request generation separately rejects stale callbacks; a failed outer selection does not revoke the current editor's preview capability. A same-project, same-revision refresh preserves the existing committed owner and preview; a newer revision resets preview, and account/access/store lifetime remounts retain their existing fences. A delayed adopted-closure refresh updates only the exact owner's adopted map and keeps an already published preview; an unsuccessful newer request does not revoke that committed owner. Preview cleanup preserves adopted graphs and does not remove picker choices or author input. This bounds that registry's obsolete previews; it does not bound author drafts, imported completion graphs, all caller-held views or the browser heap.

```sh
node scripts/optimization/measure-world-ownership.mjs --suite supplemental --output /absolute/unique/output
```

It verifies literal product bytes, identical driver overlays, original fixture/generator hashes and actual Vite build ZIP/member bytes. Every output directory is new; failed attempts and partial UI retention boundaries are retained. Check mode starts no interval clocks, numeric probes or heap observations. Actual HTTP App proofs include an ordinary idle SyncPanel refresh with a held same-revision read, local fixed account/session, zero sends and only inert shares/members metadata. They also cover rejected preview input, late source 2→3→2, immutable detail resolution, all six source choices and the adopted edition. A real completed import followed by a rejected editor read also preserves the current editor, a preview already pending when rejection settles, and a subsequent source 2→3→2 detail lookup. A held pin refresh requires the newer edition's distinct literal detail, preventing an older-edition fallback from satisfying the oracle. This discriminator belongs to a separately hashed UI-only fixture; original/core fixtures stay unchanged. Counter/heap capture is intentionally not run before independent reviews.

After review, capture mode separates OFF API elapsed from a separately seeded ON numeric run. Failed OFF calls keep actual elapsed; ON settlement failures retain partial counters and a separate observation error; interruption retains active intent and prior rows without inventing completion. Store collection/epoch counts and canonical JSON bytes are read outside intervals. UI registry gauges are available only on supporting candidate sources; unsupported baseline metrics remain UNKNOWN. Payload estimates exclude runtime/IDB overhead. Optional `--mode capture --heap true` uses a separate fresh context and actual CDP `Runtime.getHeapUsage`; instantaneous GC/JIT/transient/browser-scope values establish neither peak nor reachable retained memory nor release acceptance. No forced GC.
