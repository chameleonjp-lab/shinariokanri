## 各工程で必要な証拠

- 要件IDと受入試験IDをPRへ記載し、型・参照・状態処理の意味ある試験、画面操作、失敗系を対象に合わせて実行する。単に表示できたことを状態規則の合格にしない。
- 実行結果は合格/失敗/未実行/対象外の理由と、対象commit・データ・端末/ブラウザー・手順へ対応させる。WP23は全工程の証拠を統合する。
- 完了済みの確認を再実行する範囲は変更の影響から選ぶ。全要件削減による目標達成や未実行の合格扱いを認めない。
- 同期の接続先、外部アダプター、公開先と費用は[判断表](../decisions/ARCHITECTURE_DECISIONS.md)の条件を満たして具体化する。現段階では接続先を作成しない。

依存関係と全要件の担当工程は[追跡表](TRACEABILITY.md)、ケース別の手順は[受入試験](../quality/ACCEPTANCE_TESTS.md)を参照。
