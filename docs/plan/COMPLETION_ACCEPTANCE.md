## 実端末と性能の最終条件

実端末のブラウザー表と数値は[品質仕様](../spec/NONFUNCTIONAL_REQUIREMENTS.md)を維持する。自動Chromium/Firefox/WebKit、初期画面の自動アクセシビリティ、実日本語入力、VoiceOver/NVDAを別の結果にする。

| 計測 | Standard目標 | 範囲 |
| --- | --- | --- |
| 選択・一覧・期間 | p95≤200ms | 入力→利用可能な描画 |
| 検索 | p95≤500ms | 確定query→正しい先頭結果 |
| 保存 | p95≤1,000ms | コマンド検査開始→端末commit。500ms入力待ちを含めない |
| 取得済み起動 | p95≤3秒 | タブ開始→一覧で編集可能 |
| 年表/図の移動 | p95 frame≤33.4ms | 操作区間。全件DOMを作らない |
| Large検索/初回表示 | p95≤2秒 / ≤10秒 | 元の品質仕様に従い結果/進捗を分割表示 |

対象操作を30回測定し、p95は昇順の29番目（nearest-rank法）を採用し、生の30値も残す。実件数・fixture hash・添付量・履歴量を記録する。Standardは20MiB以下、Largeは100MiB以下の添付を用意し、最小/最大寄りの条件を区別する。レビューの添付0bytes・二回15.232/15.921秒は比較用観測で、内部保存p95の値ではない。

## 完成判定と公開の順序

同じ完成候補commitで全116受入、全24工程、6回帰群、実端末・手動支援技術・性能・復元・実同期・実権限・互換性・独立レビュー・現行費用の証拠をまとめる。新しいソース変更があれば影響する証拠を取り直す。無関係な証拠を引き継ぐ場合は旧検証commitと変更影響を記録し、候補commitで該当条件が変わらない根拠を残す。

`scripts/check_release.py`に渡すrelease-evidenceは検証対象commitのActions artifactとして保存する。文書検査を公開合格へ転用しない。公開先/直リンクの事前確認ができた候補を提出し、公開後のbuild-info・素材・保存/再読込・更新も確認する。
