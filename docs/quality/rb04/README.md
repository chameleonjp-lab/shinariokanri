# RB04 執筆・作者別案・章の試読

この段階は WP10 の REQ-B13/B20/F03/F04/F05/F06/F25/N19 を結合する。正本、作者別案、ゲーム内経路、公開版を別に扱い、別案は完全保存へ含む作者用の保存情報とする。

## 表示と入力

人物・組織・場所・章・筋の一覧は共通の場面IDを使い、章と場面の提示順へ従う。人物の変化だけ世界時点順にも切り替えられる。筋から外しても本文は消さず、章を移動しても出来事の日時は変えない。要約、本文、作者メモは分離する。

作者別案は正本または保存版から分岐する。名前、制作状態、通常の情報項目、構成雛形を別案の入力へ変更し、新しい不変版へ保存する。正本との差分を選び、採用記録と正本を一括保存する。没の章・場面は自動試読に含めず、明示的な没の経路は理由を示して止める。

未保存の入力と未確定なJSONは別案・情報ごとに保持し、画面や作品を移動しても残す。保存中の入力を止め、失敗時は名前と分岐元を消さない。保存完了を待たずに画面を離れた場合も、ホストが自分の保存完了を下書きへ反映する。保存中に別の画面で加えた入力は消さない。第三者の更新へはこの処理を使わず、古い入力の保存を止める。

本文編集は通常の文章選択・ルビ・リンク編集を使い、コードポイント位置の外部参照も追従する。位置を一意に決められない参照は再リンク待ちとする。固定された履歴参照は動かさない。

章の試読は選んだ版の章・場面・本文を使う。記録付き試読は共有の提示処理で状態と条件を更新し、提示していない場面を証拠に数えない。開始状態と経路を通常の保存で固定し、復元後も同じ版で再検証する。作者別案の保存済み版も独立して試読でき、その画面内の記録を正本へ混ぜない。

## 局所検証と範囲

`tests/browser/rb04-author-regressions.mjs` は実際のReact部品を使い、保存完了時期を制御した注入ホストで入力保持、競合、Unicode位置、固定版の表示、本文リンクの版・ブロック・文字位置の保持を検査する。Chromiumと実WebKitで12群の厳密な検査が通過した。native保存や通常Appの合格結果とは分ける。

`tests/rb04/workspace.spec.ts` の4ケースは構成・通読・別案・雛形の部品操作を検査する。`tests/e2e/writing-workspace.spec.ts` は通常Appからnative保存・再読込・完全保存・別案を含む複製復元、参照値と本文の採用、章と場面の並べ替え・移動・筋からの除外、固定版の章読み通しを検査する。結合結果と検査対象のhashは[結合検証](INTEGRATION.md)に保持する。

これらは計画の116受入、実端末・支援技術、完成版の実同期、最終公開の代替証拠ではない。
