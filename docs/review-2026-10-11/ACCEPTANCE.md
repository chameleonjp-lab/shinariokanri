## 4. 記録schemaと判定

一実行はrunId/caseId/requirementIds/targetCommit/productTree/buildHash/base/fixtureHash/seed/environment/procedure/actualResult/negativeResult/evidencePath/evidenceSha256/checkedAt/resultを持つ。端末は機種/OS/ブラウザー版/読み上げ/文字拡大、接続試験は専用構成の識別子と役割を記録し、token/本文/秘密は公開ログへ含めない。

| 結果 | 条件 |
| --- | --- |
| passed | 同一候補の全必須節と正常/例外を観測し、証拠を取得できる |
| failed | 実行し、期待動作/閾値/同一性に不一致がある |
| blocked | 入力・実環境・接続等の前提不足で判定できない。原因と次操作を記録する |
| not_run | 当該固定候補でまだ実行していない |
| cancelled | 利用者/検査者が中止し、確定点とデータの保持を記録する |

既存release checkerが定義する原116/24/6と公開条件を最終判断に使い、この追加データから自動でpassedへ変更しない。部分成功・旧候補成功・模擬端末を最終合格へ数えない。実結果を追加するときは今回の監査データを書き換えず、別runの記録を作る。
